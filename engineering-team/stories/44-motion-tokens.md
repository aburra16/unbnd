# Story 44: Two-tier motion tokens, the global reduced-motion block, and the motion CI guard

**Status:** Draft
**Created:** 2026-06-03
**Type:** Refactor (with one deliberate accessibility addition — see Background)

## Background

This is epic story 7 of Epic 0001 (Overhaul-ready design system, `@unbnd/ui`), the motion axis and the last of the token-ish axes. ADR 0038 (Accepted, 2026-06-03) is the umbrella decision. Six foundations it depends on are already merged: Story 38 stood up the `@unbnd/ui` package and relocated the token sheet (it now lives at `packages/ui/styles/tokens.css`); Story 39 stood up the Playwright visual-regression harness with committed baselines and a CI `visual` job that fails on any pixel diff (that harness is the gate this story is held to, and its animation-frozen capture is load-bearing here — see Constraint 2); Story 40 established the two-tier-token-plus-guard pattern this story follows, introducing the two-tier color tokens, fixing the live token drift, unifying the genre palette, and landing the first CI guards under `packages/ui/test/`; Story 41 carried that pattern up to type (value-keyed raw tokens behind thin semantic aliases); Story 42 carried it to spacing, including the multi-value-shorthand handling this story's `transition` shorthand echoes; and Story 43 carried it to radii, elevation, z-index, and breakpoints. This story repeats that shape for motion.

The audited and re-verified current state motivates the work (ADR 0038 §"Verified current state", "Motion"; re-confirmed against `main` today):

1. **Zero motion tokens.** The token sheet carries no duration or easing tokens. Every transition timing and easing in the app is a raw literal in component CSS.

2. **Roughly 29 `transition` declarations, zero `@keyframes` / `animation`, zero longhands.** The audit counted 29 `transition` declarations; the count is confirmed at 29 against `main` today. There are no `@keyframes` blocks, no `animation` declarations, and no `transition-duration` / `transition-timing-function` / `transition-delay` longhands in the web CSS today. There is also no runtime-injected motion: zero `transition` or `animation` strings appear in any `.tsx`. The exact per-value breakdown is the Architect's and Implementer's to confirm; the PO does not enumerate it as a contract. The PO's read of the distinct in-use values, for grounding the no-consolidation constraint only: a small set of durations (`120ms`, `140ms`, `200ms`, and a `0.15s` form in `FollowButton.css`) and a single easing keyword (`ease`).

3. **`transition` is a shorthand.** Like the spacing `padding` / `margin` shorthands (Story 42) and the `box-shadow` geometry (Story 43), `transition` packs several components into one declaration (`transition: color 120ms ease` — property name, duration, easing) and frequently carries comma-separated layers (`transition: background-color 0.15s ease, border-color 0.15s ease, color 0.15s ease`). The property name and the comma-separated layer structure stay; each duration component and each easing component maps to a token. This makes the migration mechanically closer to Story 42/43 than to the single-value type and color sweeps.

4. **No `prefers-reduced-motion` handling anywhere.** This is the accessibility gap the ADR calls out explicitly (ADR 0038 §"Verified current state", "Motion": "zero `prefers-reduced-motion` handling anywhere. This is also an accessibility gap."). Today a user who has requested reduced motion at the OS level still gets every transition at full duration.

ADR 0038 §1 ("Complete, themeable, two-tier token layer") names the motion axis: raw `--u-raw-duration-{instant,fast,base,slow}` and `--u-raw-ease-{standard,emphasized,exit}`, surfaced through semantic aliases (for example `--u-duration-control`, `--u-ease-control`). ADR 0038 §1 also specifies the reduced-motion mechanism in its own words: **"a global `@media (prefers-reduced-motion: reduce)` block in `@unbnd/ui` zeroes the motion-duration tokens, so every motion that reads the tokens degrades automatically."** ADR 0038 §6 names the motion guard: **"No raw `transition`/`animation` durations or easings outside the motion layer,"** plus, per the epic story-7 line, **"presence of the reduced-motion block."** The guard is to be built as a Vitest test under `packages/ui/test/`, mirroring the Story-40 color guards, the Story-41 type guard, the Story-42 spacing guard, and the Story-43 shape/breakpoint guards, which themselves mirror `packages/trust/test/architecture.test.ts`.

The epic's operating principle is "same pixels, better structure". House-rule anchors: `CLAUDE.md` "Brand tokens are the visual source of truth" (this story extends that source to cover the motion axis) and "No new lint/typecheck/build tooling without an ADR" (this story adds no tooling; the guard is a Vitest test under the existing `pnpm -r test`). Governing ADR: 0038. A refining ADR may be warranted, because naming the raw duration/easing scale for a value set that is not a clean ramp, the `transition`-shorthand handling, and the exact reduced-motion mechanism are real design calls (see open questions).

### Two central constraints (both are load-bearing)

**Constraint 1 — No consolidation (same lesson as Stories 40 to 43).** Mint one token per *distinct in-use value*. Do not snap near durations together or normalize across notations. Keep each distinct in-use duration distinct (do not collapse `120ms`, `140ms`, `200ms` onto a "cleaner" set), and keep the single easing as it is. The `0.15s` form is a specific instance of this: it is written in seconds, not milliseconds, and the Architect must decide whether it is preserved byte-identically as `0.15s` or treated as the same value as a `150ms` token; either choice is acceptable only if the resolved transition is byte-identical and no other near-value is snapped to it. Any genuine rationalization onto a cleaner motion scale (snapping durations together, retuning easings, changing the feel of any motion) alters behavior and is a separate, intentional motion-design story, not this refactor.

**Constraint 2 — The reduced-motion block is a DELIBERATE ACCESSIBILITY ADDITION, not pure refactor (flag prominently).** Tokenizing the durations and easings is zero-diff: it changes where the value is defined, not what it is, and the Story-39 `visual` harness (which captures at no-preference with animations frozen) confirms the default render is byte-identical. Adding a global `@media (prefers-reduced-motion: reduce)` block that zeroes the motion-duration tokens is **net-new behavior** for users who request reduced motion — there is none today, which is an accessibility gap. It is the one intentional behavior change in this story, and it is sanctioned by ADR 0038 §1. It does **not** change the default-state render: the harness captures at the no-preference media state with animations frozen, so the baseline stays zero-diff and no baseline is updated. The framing to hold honestly: the duration/easing tokenization is a behavior-preserving refactor; the reduced-motion block is an intentional, ADR-0038-sanctioned accessibility improvement layered on top, affecting only users who have requested reduced motion. The Architect confirms the exact mechanism (zero the duration tokens, per ADR 0038 §1) and confirms it leaves the default baseline zero-diff.

## User-facing description

As an Unbnd engineer, I want the motion axis modeled as two tiers in `@unbnd/ui` (raw value-keyed durations and easings behind thin semantic motion aliases) with the app's transitions referencing only the tokens, a global `@media (prefers-reduced-motion: reduce)` block that zeroes the motion-duration tokens so token-driven motion degrades automatically, and a CI guard that forbids raw transition/animation duration or easing literals outside the motion layer, so that a future motion change becomes a token change instead of a 29-site sweep, the gain is held by CI instead of by review vigilance, and the standing accessibility gap (no reduced-motion handling) is closed.

The duration/easing tokenization is developer-facing infrastructure: no Reader, Curator, or Author sees any difference in the default render, which the Story-39 visual-regression gate confirms is byte-identical. The reduced-motion block is the one user-facing change, and it benefits exactly the users who have asked their OS for reduced motion: for them, token-driven transitions collapse to instant, which is the accessible behavior the app lacks today.

## Acceptance criteria

Testable from the outside.

- [ ] Given `@unbnd/ui`, when the motion tokens are inspected, then they are two-tier: a raw tier of literal duration and easing values (per ADR 0038 §1 Tier-1 naming, following the Story-41 to 43 value-keyed-raw approach) and semantic motion aliases that reference the raw tier and never a literal. The app references the semantic tier.
- [ ] Given the app CSS after the sweep, when it is searched for raw transition/animation duration or easing literals (numeric durations in `ms`/`s` and timing-function values such as `ease`, `ease-in`, `linear`, `cubic-bezier(...)`) outside the token layer, then none remain; transition timing and easing reference the motion tokens.
- [ ] Given every distinct in-use duration and easing value today, when it is migrated to a raw token, then it is preserved exactly; no near-durations are consolidated onto a cleaner set and the easing is not retuned, so every resolved transition stays byte-identical. The `0.15s`-vs-`150ms` notation case is resolved by the Architect such that the resolved declaration is byte-identical and no other value is snapped to it.
- [ ] Given the `transition` shorthand declarations (single-layer and comma-separated multi-layer), when they are migrated, then the property name and the layer structure are preserved, each duration component resolves to a duration token, each easing component resolves to an easing token, and the resolved declaration is byte-identical to today; the handling mirrors the Story-42/43 multi-value/shorthand approach (the Architect picks per-component `var()` substitution, longhand expansion, or another mechanism). Any `transition-duration` / `transition-timing-function` longhands or `animation` declarations, if any are present, are handled the same way.
- [ ] Given a user agent reporting `prefers-reduced-motion: reduce`, when the app loads, then a global `@media (prefers-reduced-motion: reduce)` block from `@unbnd/ui` zeroes the motion-duration tokens, so every transition that reads the tokens degrades to instant automatically. This is the only intentional behavior addition in the story.
- [ ] Given a user agent at the default (no-preference) media state, when the app renders, then it is byte-identical to before this story; the reduced-motion block does not affect the default-state render.
- [ ] Given the new motion guard, when `pnpm -r test` runs, then it (a) scans app CSS for raw transition/animation duration or easing literals outside the token layer and finds none, and (b) asserts the presence of the reduced-motion block, and passes; its allowlist names only the legitimate token-source files.
- [ ] Given the Story-40 color guards, the Story-41 type guard, the Story-42 spacing guard, and the Story-43 shape/breakpoint guards, when `pnpm -r test` runs, then they stay green (this story does not weaken or remove them).
- [ ] Given the workspace, when `pnpm -r typecheck` runs, then it passes.
- [ ] Given the workspace, when `pnpm -r test` runs, then it passes, including the new `@unbnd/ui` motion guard, all prior guards, and the existing web unit suite.
- [ ] Given the workspace, when the `apps/web` build runs (`pnpm --filter @unbnd/web build`), then it succeeds.
- [ ] Given the Story-39 `visual` job, when it runs against this story's change, then it is zero-diff against the committed baselines. No baseline is updated. If any screen diffs, that is a signal the tokenization altered pixels and must be investigated, not papered over by re-baselining.

## Out of scope

None of the following may grow into this story. The fence is the motion axis only; it is a refactor plus the single sanctioned reduced-motion accessibility addition, not a redesign.

- **Consolidation of durations or easings.** This story preserves every distinct in-use duration and easing value exactly. It does not snap near durations together, normalize notations into a single "cleaner" set, or retune the easing. Each such change alters behavior, and either the Story-39 gate would correctly fail or it would change a motion's feel the gate's frozen-animation capture cannot see. A genuinely rationalized motion scale is a separate, intentional motion-design story. **This is the first central constraint.**
- **Motion redesign.** No new motion is added, no existing motion is removed, and no motion's feel (duration, easing, what animates) is changed. The reduced-motion block is the only intentional behavior change, and it only zeroes durations for users who requested reduced motion; it does not alter the default-state feel of any motion. Restyling or adding micro-animations is later, intentional design work, not this refactor.
- **The motion util / primitive and the reduced-motion-aware JS hook.** ADR 0038 §4 and epic story 11 name a token-backed `transition()` helper/class set and a `matchMedia`-driven hook for JS-driven motion. This story tokenizes the existing CSS transitions and adds the global CSS reduced-motion block only; it does not build the util, the hook, or route any primitive interactions through them. (There is no JS-driven motion on `main` today for the hook to serve.)
- **Any other token axis:** color (Story 40, done), type (Story 41, done), spacing (Story 42, done), radii/elevation/z-index/breakpoints (Story 43, done). Those are out. The token sheet's existing non-motion entries are left as they are.
- Primitives (`Button`, `IconButton`, `Input`, `Card`, `Pill`, `Avatar`, `Link`), the icon registry and `<Icon>` abstraction, and layout primitives (`Stack`, `Grid`, `Container`). Later epic stories. The guard allowlist may anticipate later token-source files, but this story builds none of these.
- Authoring a dark theme or any second skin. ADR 0038 §1 requires the two-tier structure to admit one; building one is epic story 13.
- Any behavior, copy, or information-architecture change beyond the deliberate reduced-motion block. The default-state render must be byte-identical, proven zero-diff against the Story-39 harness with no baseline update.
- `scroll-behavior` or a blanket `transition: none` / `animation: none` global reset under reduced motion, *unless* the Architect rules it the correct mechanism for the ADR's "degrades automatically" goal (see open questions). The PO's read is that the ADR's stated mechanism is zeroing the duration tokens; a broader reset is an Architect call, not a PO scope expansion.
- Re-pointing the `CLAUDE.md` / `AGENTS.md` "brand tokens are the source of truth" doc rule at `@unbnd/ui`, or citing the new guard in the docs. That is epic story 14; this story leaves the docs as they are.

PRD §11.3 "Out of Scope" check: this story touches no product surface (no payments, file hosting, ebook sales, bounty marketplace, social feed, reading progress, federation, or notifications). It is behavior-preserving infrastructure plus an accessibility improvement and does not approach the §11.3 line.

## Open questions

For the Architect to resolve in the Architecture phase. The PO does not pick names, scale shapes, or guard internals.

- **Raw duration/easing naming for a value set that is not a clean ramp.** ADR 0038 §1 sketches `--u-raw-duration-{instant,fast,base,slow}` and `--u-raw-ease-{standard,emphasized,exit}`, which assume tidy ramps. The in-use values may not map to those cardinalities (a handful of distinct durations, a single easing keyword today). Because byte-identical render forbids consolidation, every distinct in-use value must be addressable. The Architect decides the naming for each (value-keyed, the ADR's semantic ramp with honest off-ramp names, or another scheme) without implying a consolidation that did not happen, as Stories 41 to 43 resolved for their scales.
- **The `0.15s` vs `150ms` notation case.** `FollowButton.css` writes `0.15s` while other durations use `ms`. The Architect decides whether to preserve `0.15s` as its own raw token byte-identically, or to treat `0.15s` and any `150ms` as the same value behind one token, given that both resolve to the same computed duration. Either is acceptable only if the resolved declaration is byte-identical and no other near-value is snapped onto it.
- **`transition`-shorthand handling.** `transition` carries a property name, a duration, an easing, and often comma-separated layers. The Architect decides how the migration maps each duration and easing component to a token while preserving the property name and layer structure byte-identically (per-component `var()` substitution inside the shorthand, expansion to `transition-duration` / `transition-timing-function` longhands, or another approach), mirroring the Story-42 spacing-shorthand and Story-43 box-shadow handling. The guard must be able to parse this to tell a legitimate token reference from a raw literal.
- **Whether any `animation` / `@keyframes` exists.** The PO's audit finds none on `main` today (zero `@keyframes`, zero `animation`, zero `transition` longhands). The Architect confirms this against the build and decides whether the token model and the guard should still cover `animation-duration` / `animation-timing-function` and `@keyframes` defensively for the future, even though there is nothing to migrate today.
- **The exact reduced-motion mechanism, and confirming default-baseline zero-diff.** ADR 0038 §1 specifies a global `@media (prefers-reduced-motion: reduce)` block that zeroes the motion-duration tokens. The Architect confirms this mechanism (which token tier the block overrides — the raw durations, the semantic duration aliases, or both — so every token-driven transition collapses to instant), confirms it leaves the default no-preference render byte-identical (the Story-39 harness captures at no-preference with animations frozen, so the baseline must stay zero-diff), and decides where the block lives in `@unbnd/ui` so it ships with the token sheet.
- **Whether to also handle `scroll-behavior` / a broader reset under reduce.** Some reduced-motion implementations additionally set `scroll-behavior: auto` or a blanket `transition: none` / `animation: none` to catch motion that does not read the duration tokens. The PO's read is that the ADR's stated mechanism (zero the duration tokens) is the scope, and a broader reset is out of scope unless the Architect judges it necessary to honor the ADR's "every motion that reads the tokens degrades automatically" intent without leaving an untokenized motion firing. If the Architect rules a broader reset in, it should be recorded as the deliberate mechanism.
- **Guard allowlist scope.** Mirroring the Story-40 to 43 guards, the motion guard carries a tightly scoped allowlist. The Architect decides which files it exempts (the token sheet where the raw duration/easing literals legitimately live, the reduced-motion block's file if separate, the motion-util file if it exists by then, and any other legitimate token-source file), how the guard treats any TS-side motion constants if they exist, and how the "presence of the reduced-motion block" assertion is implemented (a grep for the `@media (prefers-reduced-motion: reduce)` block in the token layer). The allowlist names only legitimate token-source files, per the AC.
- **Runtime-injected motion in TSX.** Story 40's color case surfaced TS-side palette arrays and live drift. The PO's audit finds zero `transition` / `animation` strings in `.tsx` on `main` today, so there is no runtime-injected motion to migrate. The Architect confirms this (including computed styles, inline `style` props, and any third-party component default transitions) and decides whether the guard should also scan TSX so a literal cannot later hide outside the CSS the guard scans.
- **Whether a refining ADR is warranted.** The PO's read is plausibly yes, as for Stories 40 to 43: the raw duration/easing naming for a non-clean value set, the `transition`-shorthand handling, the `0.15s` notation decision, and the exact reduced-motion mechanism are design choices worth recording on top of umbrella ADR 0038. The Architect confirms and writes it if so.
